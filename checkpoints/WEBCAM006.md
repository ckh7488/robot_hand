# WEBCAM006 — 자세 변환 시험과 오류 장면 수집

FORM002의 형상과124메시를 보존한다. 사용자가 일부 접힘 초안은 개선됐다고 평가했지만, 검지 위치와 엄지·검지 관계는 여전히 맞지 않는다고 지적했다. 같은 기록의 원본 MediaPipe3D도 실제 손과 다르게 보였다. **이 체크포인트는 추종 품질 완료가 아니라, 수정안을 사용하면서 실패 사례를 정확히 수집하는 단계다.**

## 수정

- 기본 `shape` 시험은 네 손가락의 보정된 마디 굽힘을 전달한다. 기존 손끝 맞춤에서 검지 입력 뿌리 약66°를 출력 약0°로 바꾸고 끝마디를90°에 두던 해 선택을 피한다. 엄지 자세 보정은 엄지 관측만 사용하고 다른 네 손가락의 주먹 판정과 분리한다. 기존 position 방식은 비교 옵션으로 남긴다.
- S / `오류 자세 저장`은 같은 표시 프레임의 웹캠·화면·CAD 렌더·원본 world/normalized 좌표·변환값·현재 보정을 번호별로 저장한다. 원본 좌표를 추가 반올림하지 않는다. 저장 확인과 건수를 표시하고, 인식 없음·T 테스트 모드를 구분한다. 저장 실패에도 추종은 계속된다.
- `review_pose_case.py`로 원본3D의 세 방향 이미지를 만들 수 있다. 좌표에 길이 정규화·보정·필터를 적용하지 않는다. 평소는 수치 로그만 기록하며 사진은 명시적으로 요청한 프레임만 저장한다.

## 검사

75검사를 통과했다. 추가 검사는 마디 교환 방지, 혼합 자세와 다른 손가락의 독립성, 엄지의 국소4자유도, 보정 범위 부족, 좌우/카메라 회전, 저장 픽셀·좌표·프레임 일치, 번호 중복 방지, 인식 없음, 저장 실패 처리를 다룬다. 합성 입력의 통과는 실제 손 정확도 증거가 아니다.

`evaluate_pose_cases.py`의 합성 앱4프레임에서 버튼과 키로2건을 저장했다. 저장한 원본 좌표와 화면 픽셀이 각 표시 프레임과 정확히 일치했고, 요청하지 않은 나머지 프레임의 이미지는 남지 않았다. 원본3D 재렌더도 확인했다. 실제 사진 저장의 색상/유니코드 경로는 별도 단위검사로 확인했다.

FORM002의132입력 해시·124메시·20축·33자세를 재검사했고 기구학 오차는 최대4.3e-10mm였다. 이는 기존 외형을 보존했다는 검사이며 충돌/제작 승인이 아니다. 합성 화면·결과는 `docs/reviews/WEBCAM006/local/`에 있다.

## 실제 실행과 남은 일

기존 C/V의 숫자 기록으로 엄지 방향을 복구하고 shape 전용 형상 식별로 별도 개인 보정을 저장했다. 이전 position 보정은 보존했다. 실제 source0 실행에서713프레임·8손 관측을 처리했고 오류 없이 종료됐다. 그 실행에서 사용자가 표시한 오류 사례는0건이므로 실제 S 촬영 성공이나 실시간 품질 승인을 주장하지 않는다.

입력3D가 틀리면 이 변환은 실제 숨겨진 관절을 복원하지 못한다. C/V 각도 배율은 노이즈를 증폭할 수 있으며 엄지 뿌리 자세는 보정으로 추정한다. 엄지와 검지의 접촉·상대 위치, 자유 동작의 자연스러움은 아직 보장하지 않는다. 저장 사례의 원본3D와 실제 사진을 먼저 대조하고 인식 모델 비교/학습 필요성을 판단한다. 제조 CAD 절삭·모델 학습은 하지 않았다.

개인 촬영 이미지·보정·원시 좌표는 로컬 세션에만 남기고 커밋하지 않는다. 정확 커밋 SHA의 깨끗한 사본 재검사는 후속 기록으로 분리한다.
