# VISION001 — MediaPipe와 WiLoR 실제 저장 장면 비교

로봇 변환을 먼저 제외하고 다른 인식 모델을 시험하라는 요청에 따라, WiLoR 공식 저장소에서 연결한 WiLoR-mini를 별도 환경에 설치해 기존 저장 사진을 다시 추론했다. 초기 네 장면에 추가 저장된 주먹 한 장면도 포함되어 실제 입력은 총5장이다. 새 학습과 CAD 변경은 하지 않았다.

## 구현과 입력

`sim_3rd/hand_pose_compare`는 독립 손 검출→3D 복원→원본 점/표면 표시를 수행한다. MediaPipe의 좌표/박스/좌우/개인 보정을 새 모델에 제공하지 않는다. 저장 PNG를 BGR로 읽고 mini의 내부 RGB 변환을 한 번만 적용한다. 가장 큰 검출 손을 선택하고 실패는 빈 결과로 기록한다.

대형 체크포인트는 CPU mmap/assign으로 읽은 뒤 GTX1080에 float32로 올린다. 추론에 필요한 모델 키 누락0개이며, 추론에서 사용하지 않는 discriminator와 initialized 키47개를 보고했다. 모델 구조·학습 가중치·crop 배율을 바꾸지 않았다. Python3.12용 독립 환경과 가중치는 D: 작업 경로에 있다. 정확 소스 버전·다운로드 SHA-256·설치 버전은 `docs/reviews/VISION001/local`에 기록했다.

정면/사선 비교는 강체 회전·이동과 공통 미터당 배율만 적용한다. 사진에 되그린 2D 위치도 따로 제공한다. WiLoR의778정점을 그린 표면은 원본 정점 그대로이며, z-buffer로 앞뒤를 표시한다. 충돌·형상·관절각 보정은 없다. 개인 사진·원본 좌표·모델 파일은 커밋하지 않으며 공개 이미지는 명시적으로 합성 표시 검사만 포함한다.

## 실행 결과

NVIDIA GeForce GTX1080 8GB, torch2.5.0+cu118, float32. 예열1회 후 각 사진3회씩 동기화해 측정했다.

| 장면 | 검출 | 장면당 중앙 처리 시간 |
| --- | --- | --- |
| 1 | 성공 | 200.59ms |
| 2 | 성공 | 197.65ms |
| 3 | 성공 | 186.99ms |
| 4 | 성공 | 196.79ms |
| 5 / 주먹 | 성공 | 195.61ms |

첫 추론은2086.89ms다. 측정 시간에는 검출/3D 추론/전후처리가 포함되며 모델 적재·디스크 읽기·화면 그리기·카메라 지연은 제외한다. GPU tensor 최대 할당3,111,918,080B, allocator 최대 예약3,546,284,032B다. 전체 시스템 GPU 사용량을 의미하지 않는다. 동일 사진3회 출력의 최대 좌표 차이는0이었다. 이는 정지 입력 재현성이며 떨림 개선 근거가 아니다.

시각 검토에서는 주먹의 말림 형태가 MediaPipe와 뚜렷하게 달라지고 WiLoR 표면에서 주먹 형태가 확인된다. 사용자는 첫 비교 이미지에 대해 “WiLoR가 더 가까움”으로 평가했다. 따라서 다음 비교 후보는 WiLoR로 정하되, 엄지·검지의 상대 깊이와 드문 자세가 모두 맞는다는 판단은 하지 않는다. 정답3D가 없는5장만으로 정확도 향상률이나 모델의 일반 우위를 주장하지 않는다. 인식만 약5회/초 수준이므로 현재 설정을 즉시 고속 웹캠 제어로 교체하지 않는다.

## 검사와 남은 일

표시 검사3건: 좌우손/두 보기의 모든 점 간 거리·입체 방향/입력 보존, 잘못된 입력 거부, 표면 앞뒤 가림이 삼각형 순서와 무관함. 실제5장 독립 검출과 저장, 유한한21점/778정점, 같은 사진의2D 투영·3D 표시를 확인했다.

다음 판단은 연속 동작에서 품질·떨림·전체 지연을 비교하는 것이다. 개인화 학습에는 실패 자세의 검증된 정답이 필요하며 틀린 MediaPipe 출력의 단순 복제는 하지 않는다. 학습용 모델/데이터 선택은 별도 검토 대상이다. 이 체크포인트는 후보 모델의 로컬 정지 사진 비교를 완료한 것이며, 실시간 전환·재학습·로봇 품질 승인이 아니다. 정확SHA의 새 사본 재검사는 후속 기록에 남긴다.
