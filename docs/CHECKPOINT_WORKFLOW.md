# 체크포인트와 커밋 후 재검토

1. 현재 변경 범위와 통과 조건을 정합니다. V9 동결 파일은 수정하지 않습니다.
2. 별도 후보에서 수정하고 실제 형상 이미지, 실행 코드, 입력/출력, 가정과 미해결 항목을 함께 남깁니다. 실패한 검사는 삭제해 통과로 만들지 않습니다.
3. 비밀정보·캐시·로그·대용량 중복물을 제외하고 변경 diff를 확인합니다. 의도한 CAD 변경과 문서 수치가 맞는지 확인합니다.
4. 체크포인트 manifest와 CHECKPOINT.json을 만들고 커밋·푸시합니다. 기존 이력에 fast-forward로 추가하며 강제 푸시는 사용하지 않습니다.
5. 해당 SHA에서 detached worktree 또는 별도 clone을 만듭니다. 원래 작업 폴더의 파일이나 패키지 import 경로를 참조하지 않는지 확인합니다.
6. README와 미해결 항목부터 다시 읽고, 해시 확인 + 관절 FK + 의미 있는 형상 재검사를 실행합니다. 저장된 결과를 읽는 것과 실제 재계산을 구분합니다.
7. 대상 SHA, 환경 버전, 실행 명령, 통과/실패와 한계를 docs/reviews/에 기록하고 후속 커밋으로 올립니다. 문제를 찾으면 수정 커밋 뒤에 다시 검토합니다.

## 기본 읽기 전용 검사

~~~text
python verify_audit_evidence.py --full
python cad/modular_roots_v9/kinematics_numpy.py
python tools/check_checkpoint.py
~~~

V12·V13 형상을 변경하는 회차에서는 FreeCAD 전용 Python에서 tools/review_cad_checkpoint.py도 실행합니다. 이 검사는 원본 STEP에서 차집합을 재계산하고 저장된 조립의 실제 형상과 배치를 비교합니다. 새 remote_drive_v1 후보에는 해당 후보의 CAD 재생성·재수입과 시뮬레이션 검사를 사용하며, 과거 검사 통과를 새 후보의 성능 검증으로 대체하지 않습니다.

현재 원위 모터 재배치 후보는 CadQuery/OpenCascade 형상과 MuJoCo 동역학을 함께 관리합니다. 각 후보 폴더의 실행 설명과 실제 사용 버전을 기록합니다. CAD 생성 입력·질량/관성 계약·모터 전달비·시험 명령이 같은 체크포인트에 포함되어야 하며, 단순 캐시나 원본 작업 폴더를 참조하는 결과는 재현 증거로 인정하지 않습니다.

생성 중 소스가 바뀐 결과를 유효한 스냅샷으로 표시하지 않습니다. CAD와 동역학 실행의 시작·끝 입력 해시를 대조하고, 소스가 변경되면 완료 결과를 채택하지 않은 뒤 동결한 입력에서 다시 실행합니다. 커밋 후 검사에서는 실제 STEP의 부모·자식 보어와 축도 읽어 목표 운동학 좌표와 구별합니다.

사건 지연, 자세 정확도, 표현 자유도는 서로 다른 검사입니다. 임계각 선행·시작 오프셋·미도달 분류와 작은 진폭의 정확도, 16축의 요청 자세 손실이 보고서와 비교 화면에 유지되는지 확인합니다. 평가 정의를 바꾼 회차에서는 이전 지표를 보존하거나 비교가 달라진 이유를 명시합니다.

분석 Python과 FreeCAD Python은 별도 환경입니다. Windows에서는 각 pythonw.exe를 숨김으로 실행하고 표준 출력을 로그 파일로 받습니다. PowerShell Start-Process를 쓰는 경우 -WindowStyle Hidden이 필요합니다. GUI나 FreeCADCmd 콘솔을 띄우지 않습니다.

## 출력 격리

검토 도구의 --output 인자로 결과를 저장소 밖 임시 디렉터리에 기록합니다. 기본값은 표준 출력입니다. 검토 종료 시 git status --porcelain이 비어 있는지 확인합니다. 기존 V9 증거 보고서를 재생성해 덮어쓰지 않습니다.

새 후보 스크립트 중 일부는 reviews에 결과를 직접 씁니다. 이 경우 별도의 검토 복사본에서 재실행하고 결과 diff를 기록합니다. 모든 *.py를 순서 없이 실행하지 마세요. *_rejected와 debug_*는 실패/진단 기록입니다.

## 표현 규칙

- 같은 에이전트의 새 사본 검토는 독립 감사가 아닙니다. 확인 편향을 줄이는 절차입니다.
- 샘플이 통과했다고 모든 연속 자세가 통과한 것으로 쓰지 않습니다.
- 해시가 맞는다는 것은 자료 보존을 뜻합니다. 모델의 물리적 타당성까지 보증하지 않습니다.
- 시뮬레이터 이름보다 실제 CAD 입력, 오차·하중 모델, 재현 가능한 검사가 중요합니다.
- 새 형상의 모터 응답은 실측 전까지 미검증입니다.

커밋 메시지는 checkpoint(CPxxx): 구체적인 변경 / review(CPxxx): 대상 검토 결과 형태를 사용합니다.

## 사용자용 짧은 기록

PROGRESS.md에 체크포인트별 실제 수정, 검사 결과, 다음 일을 세 줄 이내로 남깁니다. 첫 커밋/푸시 뒤 해당 SHA와 재검토 예정 상태를 적고, 재검토 후 대상 SHA·결론·남은 일로 새 줄을 추가합니다. 자세한 설명은 docs/reviews로 연결합니다.

진행 기록과 CHECKPOINT.json은 현재 스냅샷 해시 범위 밖의 관리 파일입니다. 커밋된 모델/코드/결과 해시는 그대로 보존하며, 후속 검토는 새 파일로 추가합니다. 변경된 모델이나 코드가 나오면 다음 체크포인트를 만듭니다.
