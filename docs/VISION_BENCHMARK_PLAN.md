작성일: 2026-10-26 KST. 상태: **검사 설계만 기록. 회사 PC 추론은 시작하지 못함.**

| 항목 | 현재 근거/상태 |

| 회사 PC 데이터 | 사용자에 따르면 대부분 다운로드됨. 실제 경로·목록·압축해제·정답 주석 상태는 미확인 |

이전 D: 개인 PC 경로와 GTX1080 성능 수치를 회사 PC의 데이터·환경으로 가정하지 않는다.
다른 세션 검색에서 회사 PC 데이터의 구체적 경로는 검색되지 않았다.
HaMeR가 Vision Transformer 기반인 근거: https://geopavlakos.github.io/hamer/ .
이 근거는 사용자의 이전 세션에서 선택한 모델명까지 확인한 것이 아니다.

## 첫 실행 순서

1. 회사 PC 로컬 실행 복구 → 실제 데이터/가중치 목록과 GPU·디스크·실행 중 작업 확인.
2. 모델 3개 이름·소스 SHA·가중치 SHA를 고정. 세 번째 후보는 실제 파일과 인계 기록으로 먼저 확정.
3. 데이터별 원본/정답 경로·공식 split·이미지 수·손 인스턴스 수·손잡이 정보·3D/2D/영상·단위·좌표계·라이선스를 manifest로 저장.
4. 좌우손·가림·회전·주먹이 포함된 소규모 준비 검사로 관절 순서, 색 순서, 좌우 반전, 카메라 변환과 주석 대응을 검증.
5. 준비 검사 통과 후 세 모델을 순서대로 전체 입력에 실행. 중단 후 재개 가능한 샘플별 상태/출력을 기록한다.

데이터나 가중치를 새로 받기 전에 기존 다운로드·부분 파일·압축해제 상태를 확인한다. 원본을 변경하거나 다시 다운로드해 덮어쓰지 않는다.

## 비교 계약

- 공통 이미지 ID와 손 인스턴스로 비교한다. 원본 입력 결과를 먼저 보존하며 관절 제한/필터/로봇 변환으로 원본 오차를 감추지 않는다.
- 전체 이미지에서 검출까지 포함한 평가와, 정답 bbox/좌우 정보를 사용하는 복원 전용 진단을 분리한다. 후자의 결과를 실사용 성능으로 쓰지 않는다. MediaPipe 예측 박스/좌우를 다른 모델의 공짜 정답으로 주지 않는다.
- 검출 실패·손바꿈·주석 미지원·파일 손상·추론 오류를 별도 상태로 남긴다. 실패 입력을 분모에서 삭제하거나 오차0으로 채우지 않는다.
- 3D 정답: 모델별 관절 의미를 21점 공통 정의로 대응한 뒤 손목 기준 위치 오차, 굽힘/깊이 관계를 비교한다. 단위·카메라 좌표·좌우를 먼저 확인한다. 회전/스케일까지 맞춘 점수는 별도 보조값으로만 보고한다.
- 2D 정답: 투영 관절 오차와 검출률을 평가한다. 2D 일치나 자연스러운 외형만으로 3D 깊이 정확도를 승인하지 않는다.
- 정답 없는 이미지: 뼈 길이/해부학적 이상·변환 일관성·후보 불일치를 선별한다. 불일치 자체를 어느 한 모델의 오답으로 단정하지 않는다.
- 시간 순서와 시각이 있는 영상: 관절 뒤집힘, 정지 떨림, 빠른 동작, 가림 후 재검출 점프를 확인한다. 서로 무관한 정지 사진을 이어 붙여 시간축 성능으로 평가하지 않는다.
- 같은 하드웨어에서 예열/추론/검출/전후처리 p50·p95와 실패를 기록한다. 모델 적재·디스크 읽기·렌더·실제 카메라 지연 포함 여부를 명시한다. 개인 PC의 약190ms를 회사 PC 결과로 승계하지 않는다.
- 공식 평가 split을 우선하며 학습 데이터 중복/미확인 노출은 표시한다. 세 모델이 같은 데이터에 학습되지 않았다고 임의로 가정하지 않는다.

## 결과물과 다음 단계

모델별 전체 처리/성공/실패 건수, 조건별 오차와 실패율, 지연 표, 실패 사례 목록/비교 화면을 만든다.
공개 Git에는 코드·재현 설정·집계만 올리고 개인 사진/원본 좌표/가중치/데이터셋을 커밋하지 않는다.
원본 인식 → 로봇 관절 변환 → 필터 단계는 별도 평가한다. 새 학습은 이번 비교에 포함하지 않는다.
실제 실행을 마친 체크포인트에서 코드·입력 manifest·결과를 함께 커밋하고, 정확 SHA의 별도 사본에서 핵심 검사를 다시 실행한다.
