# hand_follow — 웹캠으로 실제 CAD 손 따라 하기

기본 형상은 `cad/accepted_form_v1`(FORM002)의124메시·20관절이다. 사용자가 수용한 손바닥150mm·엄지65/50/52.6mm 비율과 주먹을 보존한다. **외형을 맞춘 메시 미리보기이며 제작용 CAD 검증은 아니다.** 웹캠과 형상을 한 창에 표시하며 손 인식 → 관측 일관성 검사 → 관절 변환 → 필터 → 화면 적용을 각각 기록한다. 손목의 위치·회전은 고정하고 손가락 관절을 따라 한다.

현재 기본값은 사용자가 추가 자세 수집을 요청한 `shape` 시험판이다. 일부 접힘은 개선됐지만 엄지·검지의 상대 위치와 가려진 관절의 원본3D 오류가 남는다. 정확도 개선 완료로 승인하지 않았다. `S 오류 자세 저장`으로 문제가 보이는 장면과 원본 좌표를 함께 수집한다.

## 실행

이 PC에서는 `start_webcam.pyw`를 더블클릭한다. 콘솔 창 없이 실행하며 오류는 D: 작업 폴더에 남긴다. Python 3.12와 전용 패키지를 사용한다.

별도 환경 설치:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python follow_sim.py --repo D:\robot_hand
```

- 기본 카메라 요청은 640×480, 30fps다. 화면의 카메라 fps는 실제 수신율이며 30fps를 보장하지 않는다.
- `--source 1`: 다른 카메라. `--source synthetic`: 카메라 없이 합성 동작 확인.
- `--cad webcam_articulation_v1 --whole`: 이전 CAD와 참고용 전완 비교.
- `--cad form_candidate_v1`: 더 이전 외형 모델과 비교. 기본값은 `accepted_form_v1`이다.
- `--legacy-tracking`: 기존 변환/필터와 수치 비교. 기본은 관측 검사와 연속성 처리다.
- `--stabilize-motion`: 반응 지연이 큰 별도 실험 필터. 일반 실행에서는 사용하지 않는다.
- `--no-gui --seconds 8`: 화면 없이 제한 시간 실행.
- `--log-dir`: 수치 로그 위치. `--calibration`: 보정 파일 위치.
- 기본 `--retarget shape`: 보정한 마디 굽힘을 유지하며 엄지는 엄지 관측으로 계산한다. `--retarget position`은 이전 손끝 위치 맞춤, `--retarget angles`는 더 이전 각도 방식 비교용이다.
- 기본 미리보기는660×570에서 그려 확대하고 그림자를 생략한다. `--full-quality`는880×760과 그림자를 사용한다.
- 실행기는 `HAND_FOLLOW_WORK`, `HAND_FOLLOW_DEPS` 환경변수로 작업 폴더와 패키지 위치를 바꿀 수 있다.

## 사용

창을 클릭한 뒤 키를 누르거나 화면 버튼을 누른다.

| 키 | 동작 |
|---|---|
| C | 엄지도 펴고 편 손을 약2초 유지. 관절 영점과 엄지 방향 보정 |
| V | C 이후 엄지를 감싼 주먹을 약2초 유지. 각 마디와 엄지의 주먹 기준 보정 |
| S | 오류 자세 저장. 같은 표시 프레임의 웹캠 사진·화면·원본3D·변환값을 저장하며 번호 표시 |
| X | 개인 보정 초기화 |
| T | CAD 자체의 주먹 자세 확인. 화면에 테스트 모드가 표시되며 다시 누르면 추종 재개 |
| 1 / 2 / 3 | 정면 / 사선 / 측면 |
| H | 추적할 손 다시 선택 |
| F | 떨림 필터 켜기·끄기 |
| D | 검지의 인식각·보정각·적용각과 관절 제한 개수 표시 |
| Q / Esc | 종료. 창 닫기 버튼도 종료 |

`shape`는 네 손가락 각각의 C 영점과 V 배율을 적용한다. 손끝만 맞추려고 뿌리 굽힘을 끝마디 굽힘으로 바꾸지 않는다. 뿌리·가운데마디 변화가15도 미만이면 주먹 보정을 거부하고, 영점과 주먹을 구별할 수 없는 끝마디만 명시적으로 PIP에 연동한다. 배율은0.5–4로 제한하지만 관측 오류의 증폭 가능성은 남는다. 큰 굽힘에서 벌림을 완화하며 원래 CAD 범위로 제한한다.

엄지는 C/V에서 기록한 손바닥 상대 뼈 방향과 두 마디 굽힘으로 CAD 자세 차이를 보완한다. 엄지 자체의 굽힘 진행도에 대한 보정과 네 특징의 독립 잔차를 사용한다. 다른 네 손가락의 주먹 판정으로 엄지를 이동시키지 않는다. 이것은 개인별 자세 보정이지 정확한 해부학 복원이나 엄지·검지 접촉 보장이 아니다. 보정 범위가 부족하면 화면에 알린다.

기본 보정은 `calibration_preview_shape_<hash>.json`에 저장한다. shape 내부 형상 식별에는 엄지 길이와 관절 프레임도 포함된다. 기존 position 파일은 보존한다. 개인 보정·원시 좌표·촬영 이미지는 커밋하지 않는다.

## 오류 자세 수집과 원본3D 재검토 — WEBCAM006

자세를 유지하며 S 또는 `오류 자세 저장` 버튼을 누른다. `#001 저장 완료`처럼 확인 메시지와 저장 건수가 표시된다. 저장 후에도 추종은 계속되며 손 인식이 없는 장면도 저장할 수 있다. T 모델 테스트 중 저장한 장면은 `mode=test`로 구분한다.

세션의 `cases/case_0001/`마다 아래 파일이 함께 남는다. 자동 로그는 계속 수치만 기록하며, 사진은 명시적으로 누른 프레임만 저장한다.

- `camera.png`: 화면과 같은 좌우 반전 웹캠 입력. 관절선은 덧그리지 않는다.
- `screen.png`, `robot.png`: 같은 프레임의 표시 화면과 CAD 렌더.
- `case.json`: 원본 world21×3미터, normalized21×3, 화면좌표21×2, 좌우 판정, 프레임 번호·시각, 관측 검사/보정/출력 각도, 현재 보정, 보기 방향. 원본 좌표는 추가 반올림 없이 저장한다.

성공한 파일 묶음만 번호 폴더로 확정하며 쓰기 실패는 `.partial`로 남기고 화면에 알린다. 저장 실패 때문에 웹캠을 종료하지 않는다. 세션의 `session.json`에는 코드/CAD 해시가 있고 이벤트에 저장한 번호가 남는다.

```powershell
python review_pose_case.py --case <세션/cases/case_0001> --output <별도폴더>
```

이 명령은 원본3D를 보는 방향만 바꿔 세 방향 이미지를 만든다. 손가락 길이·각도·깊이를 수정하지 않는다. 인식이 없으면 그 사실을 결과에 기록한다. 원본이 실제 손과 다른지 먼저 확인한 뒤 CAD 변환 오류와 구분한다.

## 추종 연속성 수정 — WEBCAM005

- 처음3관측의 다수결로 좌우 손을 선택하고 추적 중에는 고정한다.800ms 이상 손실, 큰 위치 이탈 또는 H로 다시 선택한다. 최초3관측 자체가 잘못되면 H가 필요하다. 분류 점수는 개별 관절 신뢰도로 사용하지 않는다.
- 손바닥 상대 뼈 길이의 중앙값/직전 값에서35% 넘게 달라지는 손가락은 목표를 유지한다. 정상 손가락은 계속 움직인다. 새 치수가3회 일관되면 기준을 다시 잡아 최초 오추정에 영구 고정되지 않도록 한다. 이것은 기하학적 이상 감지이며 가려진 실제 자세 복원이 아니다. 유지/재설정 횟수도 기록한다.
- 이전 position 모드에서는 해 전환을 줄이도록 이전 자세 비용과 엄지 중간점 비중을 추가했으나, 사용자 기록에서 접힘이 뒤바뀌는 문제가 남았다. WEBCAM006의 shape 시험에서는 이 손끝 역기구학을 사용하지 않는다.
- 큰 단발 각도 변화는 다음 관측으로 확인하고, 손을 다시 찾을 때는 마지막 화면 자세에서 이어 간다. 필터를 강화하기만 한 느린 실험과 구분한다. 기본 출력 필터의 합성 반응 시간은 전체 카메라/앱 지연이나 로봇 모터 지연이 아니다.
- 처리한 모든 관측을 수치로 기록하고 원본 인식각, 검사 후 각도, 변환각, 출력각, 유지 사유를 구분한다. 연속 카메라 영상은 저장하지 않는다. WEBCAM006부터 S를 누른 정지 장면만 별도로 저장한다.

`evaluate_continuity.py --output <별도폴더> --session <개인로그폴더> --render`로 동일 입력 비교를 재현한다. 이전 로그는 약10Hz 간격으로 저장됐으며 원래의 모든 처리 프레임과 실제 손 정답은 없다. 변화량 감소에는 의도한 움직임 억제도 포함되므로 정확도 개선으로 단정하지 않는다. `benchmark_continuity.py`는 같은 픽셀의 UI 구성만 비교한다.

`model_check.py`는 카메라 없이 각 엄지 관절을 슬라이더로 따로 움직이는 확인 창이다. F는 새 주먹, O는 편 손, A는 기준 경로 왕복, G는 관절 축 표시다. 기준 왕복은 엄지를 먼저 들어 올린 뒤 네 손가락을 접고 엄지를 감는다. 자유 슬라이더 조작 및 웹캠의 모든 자세가 충돌 없이 움직인다는 뜻은 아니다. `render_model_review.py`는 같은 CAD로 정면·사선·측면 이미지를 만든다.

## 이전 구현에서 바꾼 것

- 막대형 모델을 실제 CAD로 교체했다. 조립된 세계 좌표의 STL을 각 관절의 중립 좌표로 변환한다. 원본 외형 CAD는 보존하고, 별도 관절 후보에서 엄지 두 바깥 굽힘축을65도 틀고 직각인 뿌리축 사이를21mm 띄웠다. 실제 핀·구멍·지지부와 시뮬레이션 축에 같은 변환을 적용한다.
- 깊은 굽힘에서 투영 방향이 뒤집히는 오류를 수정했다. 기존 코드는 뿌리95° / 가운데90° / 끝65°를 뿌리85° / 가운데−90° / 끝−65°로 바꾸고, 음수를0°로 제한했다. 새 계산은95° /90° /65°를 유지한 뒤 로봇 표시 범위를 적용한다.
- 이전 CAD에서는 엄지 기본 회전−40°와 두 번째 관절25°를 사용했다. 현재 FORM002는 design.json의−55°·외측 roll−65°·뿌리 높이21mm를 따른다.
- 사람 엄지의 비틀림을 고정된 CAD 축에 투영하면 주먹에서도 거의0도로 나오는 문제가 있었다. 엄지 중간점·끝점의 위치를 따르는 제한 범위 내 역기구학으로 바꿨다. 주먹을 가로지르는 엄지가 관측되면 검지와의 상대 위치를 사용하고, 접힌 손가락 외측으로 목표 높이를 보정한다. 주먹 여부만 보고 정해진 엄지 자세를 재생하지 않는다.
- 깊게 접힌 손가락에서 불안정한 벌림값을 중립 방향으로 완화한다. 가운데·끝마디 굽힘은 각각 독립적으로 전달한다.
- 손 선택에 위치 연속성과 좌우 판정 유지 시간을 적용했다. 손이 사라지면 마지막 자세를 유지하고 화면에 표시한다.
- One Euro 필터의 속도 추정을 직전 원시 입력 기준으로 수정했다.
- 카메라의 첫 프레임은 최대15초 기다린다. 실행 중 영상이4초 끊기면 종료하고 오류를 기록한다.

## 로그

기본 위치: `D:\Codex-work\robot-hand-workspace\work\hand_follow_sessions`.

`latest_session.json`에서 현재 세션 폴더를 찾는다.

- `session.json`: 카메라·필터 설정과 사용한 CAD/메시 SHA256.
- `angles.csv`: 프레임별 인식각, 보정각, 명령각, 실제 화면 모델 각도. 마지막 값은 실물 센서값이 아니다.
- `landmarks.jsonl`: 처리한 모든 관측의21개 관절점과 변환 단계, 제한 목록, 처리 시간. shape 모드의 `thumb_fit`에는 보정 진행도·독립 잔차·관절 제한·추정 여부, `shape_fit`에는 마디 전달 방식과 제한이 남는다. 이전 position 모드의 `finger_fit`/`thumb_fit`는 손끝 목표와 오차를 기록한다.
- `map_ms`, `render_ms`, `ui_ms`: 관절 계산/모델 적용, CAD 렌더, 화면 합성/표시 호출 시간을 구분한다. 실제 카메라 노출부터 모니터 발광까지의 지연 측정은 아니다.
- `events.jsonl`: 보정 요청·결과, 테스트 모드, 종료·오류.
- `status.json`: 처리 프레임 수, 손 검출 수, 실제 카메라 수신율, 최근 실행 상태.

동영상은 저장하지 않으며 카메라 사진은 S/버튼으로 명시적으로 요청한 프레임만 저장한다. 테스트 모드는 로그에 `mode=test`로 구분한다. 입력→각도 시간에는 카메라 노출·USB 수신 이전 지연과 화면 표시 지연이 포함되지 않는다.

python evaluate_pose_cases.py --output <별도폴더>

검사는 원본 CAD 중립 메시 위치,20축 이름 연결, 다른 손가락의 독립성, 주먹 끝점 이동,90° 전후의 굽힘, 실제 MediaPipe 공식 사진에서 추출한 관절점, 좌우손·카메라 회전, 보정·추적 소실·필터를 다룬다. 공식 샘플의 원본/좌우 반전 좌표는 `tests/data/mediapipe_poses.json`에 출처와 함께 보존한다. 합성 손의 왕복 검사만으로 실제 웹캠 품질을 판정하지 않는다.

`evaluate_tracking.py --session <개인 세션 폴더> --output <개인 결과 폴더>`는 완료된 C/V 기록에서 위치 보정을 재구성하고, 같은 관절점·시각·필터를 두 방식에 넣어 비교한다. 결과 폴더의 보정 파일은 개인용이고 `summary.json`과 CAD 비교 이미지는 집계 근거다. `--save-trace`를 지정한 전체 재생 기록도 개인 폴더에만 보관한다. 최대10Hz로 남은 기록이므로 원래 전체 프레임의 C/V·실시간 동작과 완전히 같지 않다. 닫힌 구간의 인접 각도 변화는 실제 움직임과 관절 한계 도달도 포함하며 정지 떨림이나 실제 손의 정확도 수치로 해석하지 않는다.

이 화면은 자세 미리보기다. 새 모델은 자체 관절 범위·주먹 목표·엄지 축을 design.json에서 읽는다. 실제 STEP의 지정 자세에서 주요 구조물 겹침과 손끝 간격을 검사한 범위는 `cad/webcam_articulation_v1/generated/motion_review.json`에 기록한다. 연속 경로 전체, 모든 자유 조합, 모터·줄·실물 성능은 검증하지 않는다. 엄지 외측 위치 보정은 실시간 메시 충돌 검사나 물리 접촉 해석이 아니다. 사람 엄지와 CAD 엄지의 축·비율 차이로 도달하지 못하는 위치는 남으며, 목표 오차25mm 초과를 화면에 표시한다. 가려진 마디의 깊이 추정 오차도 남는다.

이전 position 방식의 손끝 높이 보정은 shape 방식에 적용하지 않는다. 외피 전체·손가락 사이의 충돌을 막는 기능은 아니다. 현재 외형은 FORM002에 동결돼 있고 제조 검토는 별도 CAD 작업에서 진행한다.

`replay_in_sim.py`는 기존 `sim/remote_drive_v1` 동역학용 연구 도구로 남겨 둔다. 새 외형 CAD의 성능 평가 도구가 아니며, 그 결과를 현재 화면 모델의 실제 성능으로 해석하면 안 된다. 최신 외형과 구동 설계 작업은 별도 프로젝트 경로를 따른다.
