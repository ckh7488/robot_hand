# 새 관절 CAD의 구동 진단

`cad/articulation_drive_v2`의 실제 부품 질량·무게중심·관성을 20축 동역학에 연결한다. 기준은 `webcam_articulation_v1`의 뿌리 `-Z`, 굽힘 `+X`, 엄지 굽힘축 높이 21mm, 엄지 바깥축 `Rz(25°) @ Ry(-65°)`와 PIP 최대 135°다. 이전 `form_drive_v1`의 기하·뿌리 오프셋·축 부호·성능을 승계하지 않는다.

이 모델은 **충돌과 제작 완료를 검증하지 않는다.** 명시한 부품 `body`를 강체로 묶는 것은 계산 가정이며, 실제 연결·핀 고정·베어링·케이블 경로가 완성됐다는 뜻이 아니다. 누락된 부품이나 질량에 임의 기본값을 채우지 않는다.

## 입력과 검증

- `model_adapter.py`: 새 CAD의 관절 체인과 명시적인 부품-강체 연결. 부품 COM 관성을 평행축 정리로 합치고, 전체 텐서를 관절 좌표로 회전한다. 위치는 mm에서 m로 한 번 변환하며 관성은 kg·m²를 유지한다. MuJoCo 입력은 NumPy의 대칭 고유값 분해로 얻은 주관성값과 회전으로 표현하며, 컴파일 뒤 전체 텐서를 다시 구성해 원본과 대조한다.
- `build_contract.py`: `design.json`, `generated/scene.json`, `generated/mass_inertia.json`, 전체 손 STEP의 해시를 확인한다. `arm_reference`는 고정 손 시험의 움직이는 질량에서 제외한다. 부품 목록·body·체적·밀도·질량이 어긋나면 중단한다.
- `test_adapter.py`: 실제 webcam MuJoCo의 20축과 중립·주먹 경로·개별 관절·복합 자세 28개를 대조한다. 앱 코드는 `31ba43fd4ab6393945a612b46c7b279de11a5267`의 원본 3개 파일을 `reference_webcam_31ba43f`에 고정하고, 해시 검사 후 별도 모듈 이름으로 읽는다. 작업 중인 웹캠 앱은 import하지 않는다. `--contract`가 주어지면 새 실제 질량과 컴파일된 모델도 확인한다. 합성 질량은 단위 검사에만 사용한다.
- `test_screen.py`: 주먹 경로와 역순 시간, 범위 초과 거부, 원본 parameter 유지, 미응답·사건 누락·수렴 실패 보존을 검사한다. 물리 적분은 실행하지 않는다.

유한 모터 힘은 `sim/form_drive_v1/reference_06b9ab4`의 해시 고정 CP006 모델을 사용한다. 해시 고정된 기존 adapter에서는 일반 입력 검증과 reference 로더만 재사용한다. 기존 형상 로더와 부호 변환은 호출하지 않는다.

## 이번에 선언한 가정

`parameters.json`은 이전 `drive001/parameters.json`의 모든 수치를 그대로 복사하고 원본 해시를 남긴다. 수신 후 서보 입력까지 2ms, 전류에서 환산한 토크 상한, 속도에 따른 토크 감소, PWM 변화율, PD, 케이블 탄성·마찰·유격을 유지한다. 실제 서보나 이번 형상에 맞춘 보정값이 아니다.

`transmission.json`은 20개 모두 케이블 구동, 모터 스풀 8mm, `motor_angle = A @ joint_angle`, `A = I`를 선언한다. **상위 관절 움직임으로 생기는 추가 줄 길이가 완전히 제거된다는 미검증 비교 조건**이다. 상위 관절 때문에 모터 속도가 더 필요한 효과뿐 아니라 상위 관절에 전달되는 토크도 제거된다. 현재 CAD에 이를 실현한 전달 장치가 없으며, 구동안으로 채택할 근거가 아니다. 케이블 탄성과 유한 모터 힘까지 제거한 이상적 관절 구동과는 구분한다.

## 제한된 네 번의 계산

`run_screen.py`는 `small5`와 새 CAD의 깊은 주먹을 각각 125µs와 62.5µs 간격으로 계산한다. gain이나 모터 용량을 탐색하지 않는다.

주먹은 초기 0.15초 정지 후 **0.6초 닫기 → 0.3초 유지 → 0.6초 역순 열기 → 0.3초 유지**다. CAD의 fraction `0, 0.2, 0.75, 1`을 유지하고 각 구간을 minimum-jerk로 연결한다. 이는 비교용 요청 동작이며 사람의 실측 속도가 아니다. 범위를 넘으면 클리핑하지 않고 오류로 남긴다.

중간 waypoint의 사건 관측 창은 다음 waypoint 시작에서 끝난다. 창 안에서 도달하지 못한 사건은 그대로 `missing`이다. 뒤의 동작에서 넘었다고 성공으로 바꾸지 않는다. 이 미도달은 해당 waypoint 조건의 실패이며, 100ms 늦춘 전체 경로 자체가 불가능하다는 증명은 아니다. 마지막 닫힌 자세와 열린 자세에서는 전체 20축의 유지 오차와 정착 여부도 따로 기록한다.

사건 시점·미도달·초기부터 임계값을 넘은 상태·10ms를 초과한 선행, 같은 시각의 최대 오차, 작은 동작에 비례하는 임시 유지 허용폭, 전류 proxy 포화·전압 포화·PWM 변화율 제한을 모두 보존한다. `-10ms` 선행 기준과 `max(0.1°, min(3°, 0.1 × 이동각))` 유지 허용폭은 잠정 수치 판정이며 사용자 정확도 요구나 센서 실측 분해능이 아니다.

수렴 판정은 미리 고정했다. 같은 시각의 전체 관절 차이는 small5 **0.02° 이하**, 주먹 **1° 이하**여야 한다. 모든 사건의 식별자·분류와 유지 판정이 같고 대응 사건의 지연 차이는 **2ms 이하**여야 한다. 주먹의 1° 기준은 0.1° 유지 오차의 정밀성을 보장하지 않는다. 실패한 수렴이나 누락 사건을 제외해 50/100ms 통과로 표현하지 않는다.

## drive002 결과

최종 CAD contract로 실제 질량·좌표 검사 13개와 명령·판정 검사 5개를 통과했다. 네 계산 모두 완료됐고 입력 해시가 유지됐다. 수렴 검사는 **1/2 통과**다. 아래는 62.5µs 결과이며, 지연 칸은 시점을 식별할 수 있는 사건만의 최대값이다.

| 동작 | 유효 사건 최대 지연 | 시점 불명/미도달 | 선행 사건 | 최대 원시 각도 오차 | 유지 판정 실패 | 수렴 |
|---|---:|---:|---:|---:|---:|---|
| small5 | 78.086ms | 5/240 | 0 | 4.289° | 56/80 | 실패: 관절 차이 0.021403° > 0.02° |
| 새 CAD 주먹 | 26.914ms | 0/102 | 2 | 21.130° | 23/40 | 선언한 검사 통과: 차이 0.090944° < 1° |

small5의 5건은 시작부터 임계값을 지난 상태 4건과 관측 창 안에서 도달하지 못한 1건이다. 주먹 동작은 검지·중지 뿌리가 목표의 90%를 34~47ms 먼저 넘어가면서 큰 원시 오차를 보였다. **두 동작 모두 선언한 사건 예산을 충족하지 않았고 실물 50/100ms 통과를 뜻하지 않는다.** small5의 전류·전압 제한은 20축 모두 0%여서, 이 오차를 모터 용량 하나의 문제로 단정할 근거도 없다. 자세한 수치와 다음 분리 과제는 [진단 기록](results/drive002/diagnostic_notes.md), 원본 집계는 [summary.json](results/drive002/summary.json)에 있다.

## 실행

모든 실행은 저장소를 작업 디렉터리로 지정하고 숨김 `pythonw` 실행기와 파일 로그를 사용한다. 자식 프로세스·GUI·카메라·렌더러는 이 코드에서 실행하지 않는다. 수치 라이브러리 스레드는 1개로 설정한다.

```text
build_contract.py --cad-root cad/articulation_drive_v2 --step cad/articulation_drive_v2/generated/hand.step --transmission sim/articulation_drive_v2/transmission.json --scope <mass_scope와 limitations JSON> --output <contract.json>
test_adapter.py --contract <contract.json> --output <adapter_test.json>
test_screen.py --output <protocol_test.json>
run_screen.py --contract <contract.json> --output <새 결과 폴더> --traces <새 전체 시계열 폴더>
```

결과 JSON에는 모든 사건과 유지 판정, 명령 재생 정보, 입력 해시를 남긴다. 전체 속도의 NPZ에는 20축 명령·실제각·속도·모터 상태·힘과 제한 신호를 손실 없이 저장하며, 별도 2ms 시계열 JSON은 표시용이다. 입력이 계산 도중 바뀌거나 한 사례가 실패하면 그 상태를 결과에 남긴다. 지연 목표는 로봇 목표각 수신 이후 50ms, 상한 100ms이며 카메라·인식 지연은 포함하지 않는다. 이 진단만으로 실물 성능 또는 간섭 없는 주먹 동작을 승인하지 않는다.
